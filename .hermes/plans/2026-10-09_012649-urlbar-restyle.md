# Vitrina — urlbar restyle (search field matches tab strip, glow + blur)

## Goal
Make the focused search field and its results dropdown occupy exactly the tab-strip
width (not the whole deck), shrink inner elements to fit, remove the extra borders
and the double hover/selected highlight, and add the site-accent glow + blurred
translucency that the tabs already have.

## Current context / assumptions

- Theme CSS: `extension/themes/ink.css`. Runtime logic: `extension/api.js`.
- The urlbar is an overlay: `#urlbar-container` is `position:absolute; left:0;
  width:var(--btn-width)` (32px) and invisible/`pointer-events:none` at rest. On
  focus/open it flips to `width:calc(100vw - var(--right-gap)); opacity:1`. The
  expansion rule is at `ink.css:880-894`.
- Two width tokens already encode the tab strip's horizontal reservation:
  `--left-menu-width` (40px rest, 124px when left menu open) and
  `--tabs-right-padding` (`right-menu + pinned deck + gap`; 136px rest). These are
  set in the `:root` block at `ink.css:16-95`. The tab strip therefore spans
  `[ --left-menu-width , 100vw - --tabs-right-padding ]`.
- Accent color already exists as `--site-accent` (set by `api.js` `refresh()`,
  `ink.css:24`), used by the active-tab glow at `ink.css:1127-1129`.
- Verified native styles (from `browser/themes/shared/urlbarView.css` and
  `browser/themes/shared/urlbar-searchbar.css` on gecko-dev/master):
  - `.urlbarView-row` native hover/selected sets `background-color` on the ROW:
    `&[row-selectable]:not([selected]):hover { background-color: var(--urlbarView-hover-background) }`
    and `&[selected] { background-color: var(--urlbarView-highlight-background) }`.
  - Our theme already paints the highlight on the INNER element
    (`.urlbarView-row-inner`, `ink.css:1035-1045`). Net effect today: two stacked
    highlights (ours + native) → the "два выделения" the user sees.
  - `#urlbar[open] > #urlbar-background` switches `border-color` to
    `var(--arrowpanel-border-color)` and changes `box-shadow` (native). Plus
    `.urlbarView` has native `border-inline: 1px solid transparent`. These are the
    "дополнительные рамки" when the dropdown opens.

## Architecture / approach

This is a pure chrome-CSS theme change; no JS logic change is required (the width
tokens and `--site-accent` already exist and are maintained by `api.js`). All edits
are local to the urlbar section of `ink.css` (lines ~866-1063). The width fix
replaces the literal `calc(100vw - var(--right-gap))` with a tab-strip-width
expression so the field cannot overrun the deck; the double-highlight and
extra-border fixes override native variables and the row background rather than
fighting specificity with `!important` on the wrong element.

## Step-by-step tasks

### Task 1 — Search field width = tab strip, not deck
File: `extension/themes/ink.css`, the expansion block (currently lines 880-894).

Replace the whole `#urlbar-container:focus-within, ... { ... }` block so the open
field spans exactly the tab strip:

```css
#urlbar-container:focus-within,
#urlbar-container[focused],
#urlbar[focused],
#urlbar[open],
#urlbar-container:has(#urlbar[open]),
#urlbar-container:has(.searchmode-switcher[open]),
#urlbar-container:has(.searchmode-switcher[aria-expanded="true"]),
#urlbar-container:has(.searchmode-switcher-dropmarker[open]),
:root:has(.searchmode-switcher-panel[open]) #urlbar-container,
:root:has(#searchmode-switcher-popup[open]) #urlbar-container {
    left: var(--left-menu-width) !important;
    width: calc(100vw - var(--left-menu-width) - var(--tabs-right-padding)) !important;
    opacity: 1 !important;
    pointer-events: auto !important;
    z-index: 120 !important;
}
```

Note the added `left:` — currently the field starts at `left:0` (over the control
button) and stops at `100vw - right-gap` (over the right menu). With this change it
starts after the left menu and ends where the tabs end.

Verify: `node --check extension/api.js` (no JS changed, must still pass) and
`python -c "s=open('extension/themes/ink.css',encoding='utf-8').read(); print(s.count('{')==s.count('}'))"` → `True`.
Then pack: `pwsh -NoProfile -File build.ps1` → `Packed: dist\vitrina.xpi`.

### Task 2 — Kill the native row double-highlight
File: `extension/themes/ink.css`, add inside the `#urlbar { ... }` rule
(`ink.css:928-935`) two variable overrides so the native row background goes away
and only our `.urlbarView-row-inner` style remains:

```css
#urlbar {
    --urlbarView-hover-background: transparent !important;
    --urlbarView-highlight-background: transparent !important;
}
```

These two vars drive the native `background-color` on `.urlbarView-row` (see
context above). Keep `--urlbarView-highlight-color` untouched so selected-row text
still inverts correctly.

Verify: brace-balance check as in Task 1, then pack.

### Task 3 — Remove the extra borders when the dropdown opens
File: `extension/themes/ink.css`, after the `#urlbar[focused] > .urlbar-background`
rule (ends `ink.css:957`) add a matching rule for the open state and neutralize the
view's inline border:

```css
/* Open (results shown): match the focused look, drop the native arrowpanel border */
#urlbar[open] > .urlbar-background {
    border-color: rgba(255, 255, 255, 0.35) !important;
    box-shadow:
        inset 0 1px 0 rgba(255, 255, 255, 0.45),
        inset 0 0 0 1px rgba(255, 255, 255, 0.12),
        0 6px 22px rgba(0, 0, 0, 0.75) !important;
    outline: none !important;
}

.urlbarView {
    border-inline: none !important;
}
```

Verify: brace-balance, pack.

### Task 4 — Shrink inner elements to fit the narrower field
File: `extension/themes/ink.css`, extend the existing `#urlbar, #urlbar .urlbarView`
variable block (`ink.css:917-926`) and the `.urlbarView`/`.urlbarView-row-inner`
rules to scale the results down:

```css
#urlbar,
#urlbar .urlbarView {
    --urlbarView-favicon-width: 14px !important;
    --urlbarView-rich-suggestion-default-icon-size: 24px !important;
    --urlbarView-result-button-size: 22px !important;
    --urlbarView-item-block-padding: 4px !important;
    --urlbarView-item-inline-padding: 8px !important;
    --urlbarView-results-padding: 3px !important;
    --urlbarView-row-gutter: 1px !important;
}

.urlbarView-row-inner {
    padding-block: 4px !important;
    padding-inline: 8px !important;
}
```

Verify: brace-balance, pack.

### Task 5 — Accent glow beyond the dropdown edges + blurred translucency
File: `extension/themes/ink.css`, add after Task 3's open-state rule:

```css
/* Results panel: translucent + blurred, with site-accent glow bleeding past edges */
#urlbar[open] {
    background: rgba(14, 14, 18, 0.72) !important;
    backdrop-filter: blur(18px) !important;
    box-shadow:
        0 0 14px color-mix(in srgb, var(--site-accent, #1c1c22) 60%, transparent),
        0 10px 32px rgba(0, 0, 0, 0.6) !important;
    border-radius: 8px !important;
}

/* Accent glow on the search field itself, matching the active-tab glow */
#urlbar[focused] > .urlbar-background {
    box-shadow:
        inset 0 1px 0 rgba(255, 255, 255, 0.45),
        inset 0 0 0 1px rgba(255, 255, 255, 0.12),
        0 0 6px color-mix(in srgb, var(--site-accent, #1c1c22) 65%, rgba(255, 255, 255, 0.4)),
        0 6px 22px rgba(0, 0, 0, 0.75) !important;
}
```

Verify: brace-balance, pack.

## Tests / validation

This is a chrome-CSS theme living inside a WebExtension Experiment — there is no
unit-test harness. Validation is static + live:

For every task, after any CSS edit, run both checks before committing:

```
node --check extension/api.js
python -c "s=open('extension/themes/ink.css',encoding='utf-8').read(); print(s.count('{')==s.count('}'))"
pwsh -NoProfile -File build.ps1
```

Expected: `api.js OK` (or no output), `True`, `Packed: dist\vitrina.xpi`.

Live check (user-provided, after installing the new xpi and restarting Firefox):
1. Focus the urlbar → the field spans the tab strip only (left edge aligns with the
   first tab, right edge with the last tab / new-tab button), never overlapping the
   left control button or the right deck / pinned icons.
2. Type a query → results dropdown: exactly ONE highlight on hover, ONE on the
   selected row (no stacked double-tint), no extra square borders around the panel.
3. Confirm the panel is translucent with a blur, and has a soft accent glow bleeding
   past its corners.
4. Confirm the field itself has the same accent glow as the active tab at rest.

If a visual discrepancy remains (e.g. the panel background is painted by a different
native element than `#urlbar[open]`), the implementer should inspect with
`Ctrl+Shift+J` + a `getComputedStyle(...).backgroundColor` dump and adjust the exact
selector in Task 5 — do not guess.

## Risks, tradeoffs, and open questions

- **Risk (Task 5 selector)**: the results panel background may not be `#urlbar[open]`.
  In FF ≥ 113 the urlbar results are a popover; the painted background could be on
  `.urlbarView-body-outer`, a `.urlbarView` descendant, or an arrowpanel. If the blur
  does not visibly apply, re-target `backdrop-filter` at `.urlbarView` or the actual
  popup element found via the browser console. The glow `box-shadow` landing on the
  expanded `#urlbar[open]` is the most portable part.
- **Risk (Task 1 left anchor)**: the resting control button that opens urlbar sits at
  `left:0`; the expanded field now starts at `--left-menu-width` (40px). If the user
  expects the field to also start at the very left, adjust `left` back to `0` and
  only fix `width`. Confirm visually.
- **Open question**: whether the field must also shrink further when pinned
  extensions are present (`--tabs-right-padding` already includes them, so the
  expression handles it automatically) — no extra work expected.
- **Open question**: exact magnitude of "shrink inner elements". Task 4 uses modest
  deltas; if the user wants smaller, tune the `--urlbarView-*` tokens in one place.
- **No JS change**: keep it CSS-only; the width tokens and `--site-accent` are already
  drived by `api.js`. Do not add new per-window logic.
